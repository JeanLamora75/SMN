# SMN-481 — Coffre chiffré des clés API (Amelia)

Date : 16 novembre 2026. Branche : main. Epic : SMN-479.

## Décisions d'implémentation
- Métadonnées des connexions SMN-480 dans PostgreSQL, sans aucune clé API.
- Une clé maîtresse aléatoire par installation dans `data/ai-secrets/.vault-master-v1`, jamais incluse aux sauvegardes ZIP. Secrets AES-256-GCM par connexion et par **révision** de la fiche ; AAD lié à ID, fournisseur et révision.
- Fichiers privés `data/ai-secrets/<uuid>.<revision>.enc`. Après remplacement, seule la version confirmée par PostgreSQL fait autorité. Aucun secret en clair dans l'interface ou API GET. L'API d'écriture est réservée à l'administrateur, avec protection d'origine et contrôle de révision.
- Remplacement/désactivation/suppression en position sûre : `enabled=false`, renouvellement de statut. Les clés anciennes sont supprimées par purge ; toute purge incomplète remonte `cleanupPending`, à traiter avant clôture complète.
- Après restauration ZIP, les métadonnées doivent afficher « clé à renseigner » : ce comportement est à finaliser/tester dans SMN-487, puisque le dump PostgreSQL seul peut encore contenir un état `configured`. L'appel API futur doit vérifier **à la fois** le statut DB et l'existence/authenticité de la version correspondante dans le coffre.
- Perte/corruption de la clé maître : **aucune régénération automatique** si un fichier chiffré existe. API admin de remise à zéro globale avec confirmation `RESET_AI_VAULT`, invalidation en base et suppression locale du coffre. Toutes les clés doivent alors être ressaisies. Une clé fournisseur compromise doit être révoquée sur son portail.
- Aucun appel réseau au fournisseur n'est réalisé dans cette story. Le test API distant et la qualification des modèles gratuits relèvent de SMN-482 à 484.

## Restes à prouver (blocage de clôture)
- Tests comportementaux et de concurrence sous PostgreSQL 18 isolé ; crash avant/après commit et nettoyage des orphelins ; ACL Windows effectives et permissions Linux ; tests de suppression physique.
- La cohérence complète sauvegarde/restauration et l'absence de secret dans les archives ZIP nécessitent SMN-487 et une recette PC neuf.
- CI Windows et Linux sur **le même commit** ; publier seulement les preuves observées. Aucune déclaration de tests réussis sans résultats.
