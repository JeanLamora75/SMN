# Journal BMAD — Architecture Tickets CSV — 2026-11-13

> Reconstruction manuelle du journal de décisions à partir des échanges validés ; `memlog.py` non exécuté (scripts uv indisponibles). Les lignes sont append-only pour les prochaines sessions.

- constraint | Architecture parent : monolithe TypeScript modulaire, PostgreSQL pour l'état métier, authentification/autorisation serveur, stockage privé et FR/EN.
- decision | TCK-AD-1 | Les CSV de tickets restent des fichiers locaux, séparés par équipe et cycle ; pas de chargement des tickets en PostgreSQL. Binds : import/lecture/rapports ; prevents : duplication des sources.
- decision | TCK-AD-2 | Date métier antidatable distincte de la date réelle d'import ; métadonnées JSON associées. Binds : historique ; prevents : perte de traçabilité.
- decision | TCK-AD-3 | Colonnes CSV contraintes ; la liste exacte sera décidée plus tard. Binds : validation/analyse ; prevents : schémas incompatibles.
- decision | TCK-AD-4 | Menu Tickets avec cycle sélectionné par défaut depuis le header. Binds : UI/API ; prevents : confusion de cycle.
- decision | TCK-AD-5 | Calculs automatiques de consultation et comparaison de deux photographies ordonnées ancienne/récente ; regroupements par type, SP et préfixe Jira. Binds : analyse/rapports ; prevents : double comptage.
- decision | TCK-AD-6 | Modale de saisie d'indicateurs v33 : exclusivement manuelle ; aucune mesure calculée CSV n'alimente les indicateurs. Binds : indicateurs ; prevents : écriture implicite.
- decision | TCK-AD-7 | Listes et comparaisons exportables dans les rapports Office ; l'origine datée doit être identifiable. Binds : moteur de rapports ; prevents : divergence de chiffres.
- direction | TCK-AD-8 | Dépôt atomique, pas de remplacement silencieux, contrôle des accès et des chemins (proposition Winston).
- direction | TCK-AD-9 | Inclure CSV et JSON dans sauvegardes/restaurations, les exclure des mises à jour de code (proposition Winston).
- decision | TCK-AD-10 | URL Jira configurable dans Paramètres pour les liens /browse/<clé>, sans validation réseau des tickets lors de l'upload.
- question | Schéma CSV définitif, type des statuts terminés, collisions de dates, suppression, clôture, volumétrie, permissions détaillées et ergonomie.
- event | Documentation en cours de publication sur GitHub main, sans création Jira ni développement.
